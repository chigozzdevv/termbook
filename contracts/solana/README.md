# Solana collateral custody core

This native Solana program defines a per-credit SOL custody account and a per-credit recovery account. The collateral owner signs `Lock`; the program derives both accounts from the lock and credit IDs and binds the Monad borrower and Core, Solana genesis identity, terms hash, return recipient, amount, setup deadline, and verifier version. `Apply` carries the Monad authorization, finalized header, and inclusion proof; the account validates the proposed release or seizure against its immutable binding, nonce, revision, and deadline. Seized SOL enters the program-owned recovery account and its per-credit ledger.

The module is **fail closed**. `require_admitted_verifier` rejects every lock and every action, so this build cannot custody SOL. This avoids accepting deposits that could never be safely returned. The program ID identifies the market; each lock holds lamports in a program-derived address. `NATIVE_SOL_ASSET_ID` is the schema marker for those lamports, not a mint address. The release and seizure transition validates the exact destination, transfers only authorized lamports, preserves the rent reserve, and records the action hash after execution. `Expire` requires the same Monad authorization proof after its deadline and records a separate cancellation nonce and hash without moving lamports. Monad must prove that cancellation record before clearing a pending action. `RecoveryPayout` requires a finalized Monad authorization for the locked return recipient and records its own nonce, revision, and action hash before returning seized surplus. `FundRecovery` requires a separate Core authorization binding the recovery operation, inbox, deposit pubkey, amount, and quote hash. Funding and payout share a monotonic nonce and credit revision. `ReconcileRecoveryRefund` credits only SOL actually returned to the recovery account, up to the amount previously funded. The recovery ledger preserves its rent reserve and tracks funded and refunded SOL cumulatively.

To activate custody, implement and audit a Solana program that verifies finalized Monad consensus and the inclusion of the exact Core authorization. Pin its program ID, consensus version, bootstrap checkpoint, proof age, Solana genesis identity, and immutable ProgramData code hash. Replace `require_admitted_verifier` with an admission check for `Lock` and a verified authorization proof for `Apply`, `Expire`, `RecoveryPayout`, and `FundRecovery`. The verifier must authenticate the exact action hash against the Core authorization. A relayer signature, RPC result, or admin key is insufficient.

Monad Core has a Solana quote, 32-byte source identity, lock digest, and action digest. It still needs an admitted finalized Solana proof verifier before counting SOL locks or confirming release, seizure, cancellation, and recovery funding. The Solana program needs the corresponding finalized Monad authorization verifier before enabling locks and actions. `FundRecovery` can send seized SOL to a Core-authorized deposit pubkey; `ReconcileRecoveryRefund` can account for returned SOL, and Core requires a finalized recovery account proof to reopen that amount for funding or payout. Account balance proves returned value but does not identify Aurora as its sender. The Aurora sale route and settlement confirmation remain separate integrations. `RecoveryPayout` only returns a Core-authorized surplus to the original return recipient.
