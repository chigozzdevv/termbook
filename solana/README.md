# Solana collateral custody core

This native Solana program defines a per-credit SOL custody account. The collateral owner signs `Lock`; the account binds the Monad borrower and Core, Solana genesis identity, Credit and lock IDs, terms hash, return recipient, recovery vault, amount, setup deadline, and verifier version. `Apply` carries the Monad authorization, finalized header, and inclusion proof; the account validates the proposed release or seizure against its immutable binding and a strictly increasing nonce.

The module is **fail closed**. `require_admitted_verifier` rejects every lock and every action, so this build cannot custody SOL. This avoids accepting deposits that could never be safely returned. The program ID identifies the market; each lock holds lamports in a program-derived address. `NATIVE_SOL_ASSET_ID` is the schema marker for those lamports, not a mint address. The release and seizure transition validates the exact destination and nonce, transfers only the authorized lamports, preserves the rent reserve, and records the canonical action hash after execution so Monad can verify it. These transitions are tested but unreachable until finality verification is implemented.

To activate custody, implement and audit a Solana program that verifies finalized Monad consensus and the inclusion of the exact Core authorization. Pin its program ID, consensus version, bootstrap checkpoint, proof age, Solana genesis identity, and code/upgrade policy. Replace `require_admitted_verifier` with an admission check for `Lock` and a verified authorization proof for `Apply`. The verifier must authenticate `solana_action_hash` against the Core authorization; the account records that hash only after the release or seizure executes. A relayer signature, RPC result, or admin key is insufficient.

Monad Core has a Solana quote, 32-byte source identity, lock digest, and action digest. It still needs an admitted finalized Solana proof verifier before counting SOL locks or confirming release and seizure execution. The Solana program needs the corresponding finalized Monad authorization verifier before enabling locks and actions. A Solana recovery vault and Aurora sale route must deliver USDC proceeds to the House after seizure.

Run `cargo test --offline` from this directory.
